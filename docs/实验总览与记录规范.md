# GradCell 实验总览与记录规范

版本：2026-08-28

## 1. 实验目标与证据链

GradCell 当前实验不是单一训练任务，而是一条逐层收敛的证据链：先确认电池模型可以稳定求解，再确认 IDAKLU sensitivity 和 PyTorch 自定义反向传播一致，随后验证梯度能够穿过可行设计解码器和性能指标，最后才讨论监督代理模型与目标条件化 GradCell 的可学习性。

推荐顺序如下：

1. 软件与可行性测试：单元测试、decoder 硬约束测试、toy backend 测试。
2. Chen2020 基准：检查 SPMe 在典型 1C/3C 工况下的电压范围、状态和耗时。
3. 物理梯度 QA：比较 IDAKLU sensitivity、有限差分和自定义 VJP。
4. 端到端梯度 QA：覆盖 latent、decoder、1C/3C 仿真、soft metric 与 scalar loss。
5. 监督可学习性：随机设计仿真、固定数据划分、MLP 拟合和测试集指标。
6. GradCell MVP：K=0、K=1、K=3 逐步训练，观察验证损失、solver failure 与更新收益。
7. 高保真复核：用 DFN 对关键设计和梯度方向做统一复核。

## 2. 实验清单

### E0：代码与可行设计测试

- 入口：`pytest`
- 目的：验证 decoder 硬可行性、自定义 autograd VJP 和 GradCell 基础前反向传播。
- 主要判据：测试全部通过；随机设计满足孔隙率、非活性相和 N/P 约束。
- 限制：只证明软件行为，不证明 Chen2020 科学结论。

### E1：Chen2020 基准放电

- 入口：`scripts/run_baseline.py`
- 目的：确认 nominal Chen2020 SPMe 在指定 C-rate 下可求解。
- 输入：C-rate；当前 nominal 输入向量；固定仿真时间域。
- 输出：solver status、求解耗时、最低/最高电压。
- 建议运行：0.5C、1C、2C、3C。
- 判据：status=1、轨迹有限、电压范围合理、重复运行结果稳定。

### E2：物理层梯度验证

- 入口：`scripts/validate_gradients.py`
- 目的：隔离验证 physics input 到 trajectory/objective 的梯度。
- 方法：比较 autograd 方向导数和中心有限差分。
- 建议：先 toy，再 PyBaMM；对 `eps=1e-3, 3e-4, 1e-4, 3e-5` 做 sweep。
- 判据：误差随 eps 出现稳定平台，不能只依据一个 eps 或一个方向。

### E3：多工况物理 QA

- 入口：`scripts/qa_physics.py`
- 目的：在 0.5C/1C/2C/3C 和扩散率扰动设计上验证 forward、sensitivity、autograd。
- 特点：逐 case 写入 JSONL，支持断点续跑。
- 推荐：先 SPMe，再 DFN；先 `--mode forward`，再 `--mode all`。
- 输出：metadata、case_results、summary 和 run log。

### E4：端到端梯度传递

- 入口：`scripts/validate_end_to_end_gradients.py`
- 目的：验证 `latent -> decoder -> physics -> metrics -> objective` 完整链路。
- 设计：多个随机点、每点多个随机方向、有限差分步长 sweep。
- 输出：每个点和方向的 autodiff、finite difference、绝对/相对误差。
- 判据：报告 median 与 max error，并检查异常是否集中于 solver failure 或近零梯度方向。

### E5：Chen2020 监督数据生成

- 入口：`scripts/generate_supervised_data.py`
- 目的：从随机 latent 生成硬可行设计，并以 Chen2020 SPMe 产生监督标签。
- 标签：1C 比能量、3C 比功率、1C/3C 平滑最低电压。
- 输出：NPZ 数据集、同名 metadata JSON、批次事件记录和周期快照。
- 判据：有效样本数、失败率、目标分布、设计空间覆盖率和单位样本耗时。
- 建议规模：20 个冒烟样本；2,000 个初步实验；10,000 个以上正式实验。

### E6：监督代理模型可学习性

- 入口：`scripts/train_supervised_surrogate.py`
- 目的：判断当前设计分布到 Chen2020 标签的映射能否由普通 MLP 学习。
- 划分：70% train、15% validation、15% test；归一化只使用训练集统计量。
- 输出：逐 epoch 训练/验证损失、最佳模型、测试 MAE/RMSE/R2。
- 判据：测试集各目标 R2、误差尺度、训练和验证曲线是否一致。
- 解释边界：该实验不等价于真实电芯数据泛化，也不直接证明逆向设计可学习。

### E7：GradCell MVP 训练

- 入口：`scripts/train_mvp.py`
- 目的：训练 preference 到可行设计的 initializer，以及 K 步 learned refiner。
- 课程顺序：K=0 → K=1 → K=3。
- 输出：逐 step train/validation loss、checkpoint、最佳验证步和 early stopping 状态。
- 判据：验证损失改善、不同 preference 的覆盖、solver failure 率、K 步更新是否单调改善。

## 3. 统一实验记录目录

除 `qa_physics.py` 已有专用可恢复目录外，主要脚本现在默认在 `results/runs/` 下创建：

```text
results/runs/<时间>_<实验名>_<短ID>/
├── metadata.json       # 参数、命令、环境、Git commit、开始/结束状态
├── events.jsonl        # append-only 过程事件，可用于画曲线和定位中断点
├── run.log             # 便于人工阅读的时间戳日志
├── summary.json        # 最终指标、状态和 artifact 路径
└── 其他实验专用记录    # 如 training_steps.jsonl
```

`metadata.json` 的 status 初始为 `running`，正常结束更新为 `completed`，异常结束更新为 `failed`，并记录异常类型和 traceback。服务器任务被强制终止时 status 可能保留为 `running`，此时以 `events.jsonl` 最后一条记录判断进度。

## 4. 服务器标准运行流程

### 4.1 每次运行前

1. 确认工作树状态和 commit：`git status`、`git rev-parse HEAD`。
2. 激活固定环境并记录版本。
3. 为正式任务显式指定 seed、输出路径和 run-dir。
4. 先用 toy 或小样本冒烟测试，再扩大规模。

### 4.2 示例命令

```bash
python scripts/run_baseline.py --c-rate 1 \
  --output results/baseline_1c.json \
  --run-dir results/runs/baseline_1c

python scripts/validate_end_to_end_gradients.py \
  --backend pybamm --samples 3 --directions 3 --eps 1e-4 \
  --output results/gradient_chain_1e-4.json \
  --run-dir results/runs/gradient_chain_1e-4

nohup python scripts/generate_supervised_data.py \
  --backend pybamm --samples 10000 --batch-size 4 --seed 7 \
  --snapshot-every 100 --output data/chen2020_seed7.npz \
  --run-dir results/runs/data_seed7 \
  > results/data_seed7.nohup.log 2>&1 &

python scripts/train_supervised_surrogate.py \
  --data data/chen2020_seed7.npz --seed 7 \
  --output-dir results/supervised_seed7 \
  --run-dir results/runs/supervised_seed7

python scripts/train_mvp.py \
  --backend pybamm --steps 5000 --batch-size 2 --refinement-steps 0 \
  --checkpoint results/checkpoints/mvp_k0_seed7.pt \
  --run-dir results/runs/mvp_k0_seed7
```

### 4.3 每次运行后

1. 检查 `metadata.json` 是否为 completed。
2. 查看 `summary.json` 的主要指标和 artifact 路径。
3. 检查 `events.jsonl` 是否有失败、early stopping 或异常耗时。
4. 将输出与 Git commit、seed、backend、solver tolerance 一起归档。
5. 不覆盖不同 seed、不同 K 或不同 eps 的结果目录。

## 5. 分析与比较模板

正式分析至少回答以下问题：

- 可重复性：相同配置重复运行的均值和波动是多少？
- 数值稳定性：梯度误差是否对 eps、rtol、atol 和设计点敏感？
- 求解可靠性：失败率是否随 C-rate、设计区域或模型 fidelity 增加？
- 数据覆盖：训练/验证/测试是否覆盖相似但独立的设计分布？
- 可学习性：测试 R2 和物理单位误差是否同时可接受？
- 优化收益：K=1/K=3 相比 K=0 的收益是否超过额外 solver calls？
- 外推风险：结论是否仅限 Chen2020 SPMe 和当前设计边界？

建议最终汇总表包含：run_id、commit、seed、backend/model、样本数、成功率、耗时、主要误差或 loss、artifact 路径和结论备注。

## 6. 当前结论边界

当前代码能用于验证可微 SPMe 训练链、监督标签可学习性和目标条件化设计原型。SPMe 不是 ground truth；DFN 只能称为更高模型保真度复核；真实材料发现或真实电芯性能结论仍需要独立实验数据。质量模型仍是 stack-level proxy，ideal/nadir 和 reference front 也需要后续以严格训练 split 和高预算基线标定。
