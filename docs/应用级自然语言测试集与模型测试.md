# 应用级自然语言测试集与 Qwen+MLP 测试

## 1. 目的

本测试不是新的训练集，而是 capability-boundary 测试集。它使用产品级自然语言需求，例如：

```text
请帮我设计一款 70Ah LFP/石墨软包堆叠电芯，标称电压 3.2V，
厚度上限 20mm，外形上限 20*150*220mm，质量上限 1500g；
主要用于储能场景，25℃下 0.5C 循环 3000 次后容量保持率不低于 80%，
希望兼顾安全性、成本和低温可用性。
```

它用来检查：

1. 当前 Qwen+MLP 对真实用户语言会输出什么；
2. 相同规格的不同表述是否导致设计明显变化；
3. 输出是否满足当前七参数结构约束；
4. 容量要求与当前 Chen2020 单体模型预测的 1C 容量差距；
5. 模型是否会对它未训练的需求给出看似合法但无法验证的设计。

## 2. 生成数据集

脚本：

```text
scripts/generate_application_battery_prompt_dataset.py
```

脚本先采样结构化电芯规格，再把每组规格交给 DeepSeek。DeepSeek 一次生成 3 个语义一致、表达方式不同的自然语言需求，便于评估语言稳定性；程序本身不再使用固定句子模板。第一组结构化规格固定为 70Ah LFP/石墨储能软包示例。

`.env` 至少需要：

```bash
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_CONCURRENCY=4
```

脚本会自动读取项目根目录的 `.env`。默认不传 `max_tokens`，允许推理模型自行使用输出预算。

建议先生成一组规格，确认接口与输出格式：

```bash
python scripts/generate_application_battery_prompt_dataset.py \
  --output data/application_prompts/application_battery_prompts_deepseek_s7.jsonl \
  --text-output data/application_prompts/application_battery_prompts_deepseek_s7.txt \
  --spec-count 32 \
  --variants-per-spec 3 \
  --max-new-specs 1 \
  --require-success \
  --seed 7
```

检查正常后去掉 `--max-new-specs 1`。脚本会识别输出文件中已由同一 DeepSeek 模型完成的 `spec_id`，从下一组继续生成，不会重复付费。

生成 32 组规格、共 96 条文本：

```bash
python scripts/generate_application_battery_prompt_dataset.py \
  --output data/application_prompts/application_battery_prompts_deepseek_s7.jsonl \
  --text-output data/application_prompts/application_battery_prompts_deepseek_s7.txt \
  --spec-count 32 \
  --variants-per-spec 3 \
  --require-success \
  --seed 7
```

一次 API 请求处理一组规格并返回 3 条语言变体，因此上述设置最多需要 32 次 DeepSeek 请求，而不是 96 次。程序用不可改写占位符保护材料体系、容量、电压、尺寸、质量、温度、倍率、循环数和保持率；任何遗漏、重复或篡改都会拒收。

`.txt` 文件只包含 DeepSeek 生成的自然语言，每行一条。`.jsonl` 额外保留 `spec_id`、结构化需求、来源模型、API 用量和模型能力边界，供批量测试使用。`.manifest.json` 记录完成数量、失败记录和本轮 token 用量。

## 3. 批量测试 Qwen+MLP

脚本：

```text
scripts/test_application_prompts_physics_guided.py
```

第三张 A100 运行：

```bash
CUDA_VISIBLE_DEVICES=2 python scripts/test_application_prompts_physics_guided.py \
  --data data/application_prompts/application_battery_prompts_deepseek_s7.jsonl \
  --model-name "$PWD/models/Qwen3-8B" \
  --design-checkpoint results/deepseek_2158_physics_guided/seed_7/best_model.pt \
  --surrogate-checkpoint results/deepseek_2158_physics_guided/dfn_surrogate/best_model.pt \
  --output results/application_prompt_test_s7/predictions.jsonl \
  --report results/application_prompt_test_s7/report.json \
  --batch-size 8 \
  --local-files-only
```

测试脚本只加载一次 Qwen，然后分 batch 处理所有文本。每条输出包含：

- Qwen+MLP 生成的七个参数 multiplier；
- 对应的参数值；
- 性能代理模型输出的 1C/5C/6C 性能；
- 结构可行性；
- 请求容量与预测 1C 容量的相对误差；
- 不受当前模型支持的需求列表。

## 4. 报告指标

`report.json` 包含：

### 4.1 Structural feasibility

检查生成的七参数是否满足当前结构约束。这只能证明参数在 Chen2020 模型中可解，不能证明尺寸、重量、材料体系或寿命满足。

### 4.2 Requested vs predicted capacity

将文本中的目标 Ah 与当前 Chen2020 DFN 代理预测的 `capacity_1c_ah` 比较。对 70Ah、100Ah 等大型软包要求，当前模型预期会显示很大误差，因为它没有尺寸与并联/堆叠层数设计变量。

### 4.3 Paraphrase consistency

对同一 `spec_id` 的三种语言改写，计算生成参数的 within-spec log-RMS。数值越小，说明模型对语序和表达方式越稳定。

## 5. 必须正确解读

当前模型只训练了：

```text
Chen2020 + Regular Mode + 7个参数 + 1C/5C/6C DFN短期放电性能
```

它没有训练：

- LFP/NCA 等化学体系选择；
- 软包/方形/圆柱结构；
- 厚度、长宽、质量和堆叠层数；
- 3000 次循环寿命；
- 安全、成本和低温性能。

因此测试脚本会把这些需求标记为 `unsupported_requirements`。即使 MLP 输出了一组数值合法的参数，也不代表上述产品需求已被满足。

这两个脚本的价值是暴露当前模型的能力边界，而不是将超出训练范围的输出包装成有效电芯方案。
